Cursor 开始向 Pro、Teams 和 Enterprise 付费用户 beta 推出 GitHub 替代服务 Origin。与此同时，微软旗下的 GitHub 正经历频繁的服务中断，仅 2026 年 2 月 9 日一天内就发生了超过 5 次故障。

![](https://cdn.neowin.com/news/images/uploaded/2026/08/1786996474_cursor-github_story.webp)

### **Origin 核心功能**

Origin 首发即支持 GitHub 同步功能，允许用户将 GitHub 仓库实时镜像至 Origin，同时保持 GitHub 作为现有项目的主数据源。其他功能包括通过 Cursor agents 直接创建仓库、使用 diffs 审查堆叠式 pull requests、管理仓库设置、连接自动化流程，以及通过全新 Web 界面浏览代码。

### **第三方集成支持**

开发者可将 Origin 与 Vercel 连接以获取预览部署，也可对接 Depot 和 Buildkite 运行 CI 工作流。这些集成旨在简化从代码提交到部署的完整链路。

### **产品定位与设计哲学**

Cursor 于 2026 年 6 月在旧金山首次公布 Origin，将其定位为"agentic 时代的 git forge"。官方认为，GitHub 和 GitLab 的设计基于开发者手写代码、提交 PR、等待人工审查的传统流程，这一过程可能耗时数天。而 AI 代理能够以更快速度生成代码变更，有时甚至同时产生多个变更，这对 git 托管服务提出了完全不同的性能要求。在 6 月的演示中，Cursor 展示了单仓库内 AI 代理集群每秒推送 **22.6** 次 commit，同时维持每小时 **81K** 次 push 和 **295K** 次 clone 的负载能力。

### **GitHub 近期服务中断**

GitHub 在过去数月经历多次故障。2026 年 1 月至少发生两起因模型更新配置错误导致 Copilot 错误率达 **100%** 的事件。2 月情况更为严重，仅 2 月 9 日一天内就有超过 5 次故障影响 PRs、Actions runners、webhooks、issues、Git pushes、Pages 和 Packages 等服务。当月几乎每天都有服务事件报告。就在数小时前，GitHub 再次发生服务中断，影响核心 API 和网页，同时导致 raw.githubusercontent.com 的失败率达到 **50%**，造成全球范围内的 package 安装和 Docker 构建失败。
