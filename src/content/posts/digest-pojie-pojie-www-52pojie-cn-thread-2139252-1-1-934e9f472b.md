我设计的一套 Windows 反调试诱饵机制

我写了一个 Windows x86/x64 反调试检测测试程序，里面的诱饵机制由我自己设计。程序会主动设置两个 PEB 字段，保存预设值，在后续检查中观察它们是否被修改，再结合 API 返回值、函数入口检查和子进程校准给出检测结果。

目前我做了直接运行、调试器附加和从调试器启动的对照测试。直接运行未出现命中，x86、x64 的调试测试均记录到了诱饵变化。

**一、设计动机**

常见的调试状态查询包括 IsDebuggerPresent、CheckRemoteDebuggerPresent，以及 NtQueryInformationProcess 的相关信息类。在我的测试中，隐藏插件可以让这些查询报告无调试状态。

我由此设计了一套主动布置诱饵的办法。先把字段设置成已知状态，再观察它是否发生变化。这样，隐藏插件在处理这些字段时，修改动作本身就能进入检测记录。

本项目采用的判定约定是，已经布置的诱饵只要与本轮预设值不同，就直接判为调试命中。完整值的变化都会进入判断。界面触发由诱饵修改、返回值矛盾、入口异常或校准不符驱动。

程序以窗口状态和命中日志展示结果，主文件是 AntiDbgTest.cpp，使用原生 Win32 窗口接口。
