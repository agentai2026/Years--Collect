工作的时候经常需要使用到[虚拟机](https://www.52pojie.cn/thread-661779-1-1.html)和远程管理桌面电脑，但是在远程桌面电脑里的虚拟机复制粘贴文本一直不行，突发奇想搞了一个小脚本，提供给参考

RDP → VMware Workstation → 断网 Windows 虚拟机

一、需求

1.1 环境与场景

办公终端 A 通过远程桌面登录主机 B；B 上运行 VMware Workstation，其中一台 Windows 虚拟机 C 承载业务。出于安全要求，C 不具备对外网络，只能在 B 的 VMware 控制台中操作。

A：办公终端（Windows），RDP 客户端

B：Windows 主机，VMware Workstation 宿主机

C：Windows 虚拟机，无对外网络，仅控制台可达

1.2 问题现象

A 与 B 之间：复制粘贴正常

B 与 C 之间（VMware 控制台）：复制粘贴正常

A 与 C 之间：无法直接复制粘贴，只能在 B 上手工中转两次

1.3 目标

A、C 之间可双向直接复制粘贴纯文本

端到端时延不超过 2 秒

保持 C 的断网状态，不新增对外网络通道

不降低既有安全策略：不开放监听端口、不引入第三方云服务

重启或重新登录后自动恢复，无需人工启动

1.4 约束

C 无对外网络，A 无法直连 C，无法把链路缩短为一跳

宿主机为 VMware Workstation；若为 ESXi 则不支持 HGFS 共享文件夹，需改用虚拟串口方案

二、解决方法

2.1 根因分析

剪贴板不是端到端协议，而是每跳各自桥接的“单槽会话资源”，本身没有链式转发能力：

第一跳由 RDP 客户端完成剪贴板重定向，把 A 的剪贴板映射到 B

第二跳由 VMware Tools 完成宿主机与客户机之间的剪贴板同步，把 B 的剪贴板映射到 C

两跳互相独立：B 的剪贴板由 RDP 客户端以延迟渲染方式持有，VMware Tools 读取时可能拿不到内容或格式不匹配

结论：瓶颈在 B 的剪贴板上，与 C 是否断网无关。VMware Tools 的剪贴板通道走虚拟设备，不经过网络协议栈。要解决的是“缺少一条不依赖这两套剪贴板通道的传输链路”。

2.2 方案设计

以 VMware 共享文件夹作为独立数据通道，在 B 与 C 上各运行一个守护脚本，用两个文本文件交换剪贴板内容。整个过程不经过网络协议栈，C 保持断网即可。
